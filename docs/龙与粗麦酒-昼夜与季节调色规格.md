| # | 结论 |

## 1. 为什么不存 4 张完整色表

季节 × 昼夜 = 4 × 4 = **16 张表**，而且昼夜是**连续插值**，表根本覆盖不了中间态。

所以存**参数**，运行时算：

```
当前季节地形 16 色 + 核心 31 色
        ↓ 按所属类别套用插值后的参数
    47 个最终颜色
        ↓ 写入 64×1 RGBA8 纹理（R = 索引）
    shader 查表
```

47 个颜色的运算 + 一张 64 像素宽的纹理上传，每帧成本可以忽略。

---

## 2. 四个关键帧参数

参数含义：`ls` 明度系数／`ss` 饱和系数／`anchor` 混色锚点／`w` 混色比例。四项都支持线性插值。

| 时段 | world（世界材质） | character（角色） | fire（火光） |
|---|---|---|---|
| **黎明** | `ls 0.88 / ss 0.96 / #56697E / w 0.10` | `0.90 / 0.97 / #56697E / 0.08` | `1.02 / 1.00 / — / 0` |
| **白天** | `1.00 / 1.00 / — / 0` | `1.00 / 1.00 / — / 0` | `1.00 / 1.00 / — / 0` |
| **黄昏** | `0.92 / 1.12 / #C2703A / 0.12` | `0.94 / 1.08 / #C2703A / 0.10` | `1.06 / 1.08 / — / 0` |
| **深夜** | `0.62 / 0.84 / #232E3C / 0.28` | `0.72 / 0.90 / #232E3C / 0.24` | `1.00 / 1.12 / — / 0` |

**明度下限 `L_FLOOR = 4`**：低于此值钳制。实测这个值最优——下限设成 10 反而更糟，因为它把暗部整体推高、彼此靠拢，直接导致并阶（暗部阶从 6 掉到 3）。

## 3. 关键发现：夜景靠"混色"，不靠"转色相"

我第一版用的是"色相偏移 +10°"，结果是错的：

| 颜色 | 错误做法（色相+10） | 正确做法（混入 #232E3C 28%） |
|---|---|---|
| 中木 `#785028` | `#41351B`（偏黄褐，像脏木头） | `#3C3126`（暗冷褐，是夜里的木头） |
| 浅石 `#A09888` | 变暗但仍偏黄 | `#52514D`（冷灰，是月光下的石头） |
| 亚麻亮 `#C8C2B4` | 橄榄色 ← 明显错误 | `#7D786A`（冷灰米，正确） |

原因很简单：草/木的色相在 30–45°，**加 10° 只是更黄**，要走 100° 以上才到蓝，那时候饱和度和明度早就崩了。而"向固定冷色混合"是线性插值，几步就到，且不会失控。

> 这条经验同样适用于黄昏：向暖橙 `#C2703A` 混 12%，得到的是"被落日晒过的木头"，而不是"把木头调成橙色"。

## 4. 校验结果（实测）

| 时段 | 灰度可辨阶 | 暗部 12 色内的阶数 | 平均亮度 Y |
|---|---|---|---|
| 黎明 | 16 | 7 | 108.5 |
| 白天 | 20 | 8 | 119.8 |
| 黄昏 | 19 | 7 | 115.6 |
| **深夜** | **17** | **5** | **77.9** |

判据：灰度阶 ≥12 且暗部阶 ≥4。**四帧全部通过**，最紧的是深夜的暗部 5 阶——意味着夜里的深木、深石、暗瓦还能分开，但余量不大。

**一条使用约束**：夜间场景中，深色物件之间**必须**有描边或一块受光面分隔，不能两块深色直接相邻。

---

## 5. 火色是唯一"不服从暗化"的东西

| 颜色 | 白天 | 深夜 |
|---|---|---|
| 炉火橙 | `#E8963C` | `#F29632`（更亮更饱和） |
| 火心黄 | `#F6D08A` | `#FCD284` |

这是刻意的：如果火也压暗，夜景就没有光源了，整个画面会变成"一块灰"。**夜间画面的最高亮度必须落在火上。**

---

## 6. UI 不参与变换

`#A8342A`（危险红）、`#C9A227`（钱金）、`#4E8A5A`（成功绿）在四个时段完全恒定。UI 颜色是功能语义，不该随环境变——血条在夜里变暗红会让人读不出危险程度。

## 7. 季节：只换 6 个色

| 季节 | 草绿 | 深草 | 苔深 | 稻草 | 土亮 |
|---|---|---|---|---|---|
| **春**（嫩绿） | `#909952` | `#5E6E43` | `#495A37` | `#BFA16C` | `#907A54` |
| **夏**（浓绿） | `#68793F` | `#445632` | `#36482B` | `#BB9F65` | `#8A7550` |
| **秋**（枯黄） | `#928659` | `#696B46` | `#4E5537` | `#BFA870` | `#907C54` |
| **冬**（枯灰） | `#87866E` | `#636655` | `#4D5343` | `#9A7A59` | `#7A6A51` |

- **木、瓦、石 9 个色完全不动**——所以换季时建筑与家具不会有任何变化，只换地表。
- 一个易错点：草/苔的色相在 **76–94°**（绿偏青），要变黄必须**减**色相；我第一版加了 28°，结果秋草变成了青绿色。方向搞反是这类调色最常见的事故。

## 8. Godot 侧最小接法

```gdscript
# Autoload: PaletteService.gd
const W := 64
var tex: ImageTexture
var img := Image.create(W, 1, false, Image.FORMAT_RGBA8)
var _acc := 0.0

func _process(dt: float) -> void:
    _acc += dt
    if _acc < 0.1: return          # 每 0.1s 一次足够，昼夜本来就很慢
    _acc = 0.0
    var colors := _current_colors() # 当前季节的 47 色（核心 31 + 地形 16）
    var p := _lerp_params()         # 按游戏时间插值四个关键帧的参数
    for i in colors.size():
        img.set_pixel(i, 0, _apply(colors[i], p))
    if tex == null: tex = ImageTexture.create_from_image(img)
    else: tex.update(img)
```

要点：
- **只更新数据，不重建纹理**：用 `ImageTexture.update()`，别每帧 `create_from_image`。
- **0.1s 的更新频率够用**：昼夜几十分钟走一轮，没必要每帧。
- 全局共用一个 `ShaderMaterial`，`palette` 作为 uniform 指向 `tex`——这样合批正常。

## 9. 验收方法（两条，都很快）

1. **灰度测试**：把夜间截图转灰度，如果还能分辨"木桌 / 石墙 / 地板"三者，就算过；糊成一片说明色阶塌了。
2. **亮度峰值测试**：夜间截图里亮度最高的像素必须落在火上。如果墙比火亮，说明压暗没做对或火色提亮不够。

## 10. 剩余待定（不阻塞）

| # | 项 | 建议 |
|---|---|---|
| 1 | 季节切换要不要 300–500ms 交叉淡入 | 建议要，硬切在视觉上很突兀，而成本几乎为零（对参数插值即可） |
| 2 | 正午是否需要比白天再亮一点 | 可选。当前"白天"是基准 1.0，若要正午感可加第 5 帧 |
| 3 | 夜间窗光是否要单独提升 | 建议单独处理：窗是"外面的光"，与火不同源，可再加一组参数 |
