## NPC 系统（19 个角色 → 可交互 NPC）

### 素材核查结论（重要，别重走弯路）
- `character/人物行走/*图集.png`：240×480 = 4 列×4 行、单格 **60×120**，脚底压在格底（y≈120），水平中心 x=30。
- **没有烘焙投影**：全图 alpha 只有 0/255（零半透明像素），最底几行像素范围就是鞋底本身，脚下没有独立阴影块。
- GIF 预览（738×360，绿底 #6E6E56）同样是干净平涂背景，无脚下暗影。
- 真正看得见的是**轮廓灰雾**：脚踝/鞋侧/下摆外沿挂着一圈去饱和中性灰（约 sat≤0.18、V 40..175），压在地板上像脏影子。
- 结论：19 张图集之间**帧内容不同**（不是重复帧），行序与 walk_v5 一致（0 下 / 1 左 / 2 右 / 3 上）。

### 清理工具 `tools/clean_npc_shadow.py`
- 只处理单格 **y≥88（脚部）** 的**贴边**像素；判定三条同时满足才动手：sat≤0.18 / 40≤V≤175 / 4 邻域有透明。
- 参照色 = 3px 内非灰雾像素的中位色；参照饱和度须高 0.15 以上（本体本来就是灰的就不碰）。
- **改色不改形**：`retint()` 保留原像素明度、只换色相，BLEND=0.95。抠掉会开洞，重上色安全。
- 孤立灰岛删除**必须按 alpha 连通域**判断（≤12px 且全为灰雾）；按"灰雾集合内部连通性"判会误删合法灰铠甲边（实测误删 515px）。
- 产出：`assets/actors/npc/<原名>.png` + `_report.json`；可见改动 0~461px/张（alpha 仅 2px 变化）。
- 源文件 `character/` 不动，随时可重跑。

## 笔记本图标 v3/v4：AI 图生图成功路线（21:xx）
- 手绘 v2 被嫌"细节不够好"→ 改走 AI。**关键经验**：
  - 纯文生图 + 写实提示词 → 出光滑 3D 渲染（第一版，被否）；
  - **图生图（拿用户样图当 image1）+ 强像素提示词**（hard pixels/limited palette/no anti-aliasing）→ 出**真像素图**（好使）；
  - `input_fidelity=high` 会把样图**复刻**（用户："只让参考朝向，没让权重拉这么高"）→ 要**low**，只借朝向/构图；
  - 背景要么让 AI 直接给纯色底（提示词写死 plain flat solid magenta #FF00FF，禁 scenery/shadow/vignette），要么图生图时让 AI"书不动、背景换洋红"（fidelity=high 保书）；
  - **chroma key**：洋红系有渐变（角 (225,82,229)~主体 (255,14,255)），按「R>170 且 G<130 且 B>170」判定，比取角众数+色距稳；

- 最终采用：**AI 图生图（fidelity=high 保书 + 背景换洋红）** 那张 —— 棕皮缝线日志本 + 金色炉火印 + 米白页块 + 皮扣，斜 3/4 视角，硬像素。`tools/process_ai_notebook.py`（洋红 chroma key 版）。

## 【真·BUG】play_pose 参数遮蔽 AnimatedSprite2D.frame → 坐姿永远停在第0帧（23:2x）
- 用户反馈"你改哪了，这不和原来一样吗"：上一条的朝向逻辑其实没错（左椅→col2/右椅→col1），但**游戏里坐姿始终显示 col0（正面占位稿的奶油色矩形+两条黑腿）**，跟原来一模一样。
- **根因**：`character_animator.gd` 的 `play_pose(row: int, frame: int, ...)` —— 参数名 `frame` **遮蔽了 AnimatedSprite2D 自带的 `frame` 属性**！函数体里 `frame = clampi(frame, 0, ...)` 只改了局部参数，**精灵的 frame 属性从没被设置**，永远停在 0 → 永远显示该行第 0 格（正/背占位稿）。col1/col2 的侧面帧根本没被用到。之前 verify_customers 只断言 `animation=="sit"`（没查 frame 下标），所以一直绿。
- **修复**：参数改名 `frame_index`，用 `self.frame = clampi(frame_index, ...)` 明确写属性。
- **验证**：`tests/debug_seats.gd/.tscn`（一次性排查，读 4 张座位打印实际帧）→ 修复前全部 `frame=0 ATLAS_COL=0`；修复后 lucy/edward(col2 朝右)、simon/catherine(col1 朝左)，**方向与椅子侧别完全正确**。回归 verify_customers 20/0、prologue 15/0、npc 14/0。
- **座椅"矩形"真相**：网格源图里角色是**坐在空气上**（gridsrc_simon/lucy 实测纯灰底、无凳子）；之前以为是"座椅残留"的 tan/灰块，其实是角色**自己的长头发（露西金发垂到髋）/短裤腿/双手**（采样确认 tan≈发色而非独立板凳）。所以"矩形"= col0 占位稿的奶油色块，**play_pose 修好后彻底不出现**。顺手用 `tools/clean_v3_apply.py` 把侧面帧里**低饱和灰的抠图毛边/阴影**清了一层（保留高饱和衣物/纯白大衣/深描边/角色内部明暗）。
- **教训**：① GDScript 里**参数名绝不能和节点内置属性同名**（frame/position/scale/modulate…），否则赋值只改局部变量、静默失效；② 验收断言要查"实际显示的帧下标/贴图 region"，不能只查 animation 名。

## 台词按出场位置区分（凯瑟琳集市 ≠ 酒馆，11:0x）
- 问题：凯瑟琳在集市（village 300,782）说 `npcs.json` 顶层 `lines` =「集市收了摊我才得空进来」——那是**酒馆顾客口吻**，等于把酒馆台词搬到集市。
- 机制：`npcs.json` 的 **placement 里可写 `lines`**，有就优先、没有才退回顶层 `lines`。
  - `scripts/npc.gd::configure()`：`var own_lines = place.get("lines", [])`；非空则用它。
  - `tools/build_npc_data.py`：`CHARACTERS` 的 placement 元组支持**第 6 项 = 位置专用台词**，抽出 `_placement(p)` 统一构造（`(scene,x,y,facing,wander[,lines])`）。**改 npcs.json 必须改这个 py 再重跑**，否则重生成会被覆盖。
